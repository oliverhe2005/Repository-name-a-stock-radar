# A股自选股资讯雷达

一个面向自选股的每日自动扫描平台，默认覆盖最近 24 小时：

1. **资讯**：东方财富个股新闻
2. **公告**：东方财富沪深京 A 股公告聚合
3. **大宗交易**：东方财富数据中心每日明细，逐单列出成交额、成交价、成交量、
   折溢率、买方营业部和卖方营业部
4. **问董秘自动分流**：按股票上市市场查询指定互动平台
   - 深圳股票：深交所互动易
   - 上海主板、科创板：上证 e 互动
   - 北交所股票：全景网北交所互动专区
5. **持久化**：SQLite + 去重
6. **输出**：Streamlit 仪表盘 + Markdown 日报
7. **自动化**：工作日 17:10（北京时间）运行，可在 `config.json` 修改

## 1. 安装

建议 Python 3.11–3.13：

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
```

## 2. 首次抓取

```bash
python daily_job.py
```

数据写入 `data/watchlist.db`，日报写入 `reports/YYYY-MM-DD.md`。

## 3. 启动仪表盘

```bash
streamlit run app.py
```

仪表盘左侧可手动立即刷新，也有独立的“自选股管理”区域：

- 在“输入要增加的股票代码”中输入一个或多个 6 位代码，点击“增加并查询”；
- 在“选择要删除的自选股”中勾选股票，点击“删除所选股票”；
- 顶部“显示/查询股票”复选框只控制当前页面显示，不会删除股票。

新增代码会立即加入当前自选列表并打开对应市场的问董秘查询，不需要先刷新数据库。
在可写的本地/服务器环境中，新增代码同时保存在 `data/custom_watchlist.json`。
“备份 / 恢复自选股”可将当前完整列表导出为 `stock_watchlist.json`；Streamlit
Cloud 重启或重新部署后，导入该文件即可恢复同一列表。

## 4. 自动运行

### 方法 A：保持 scheduler 常驻

```bash
python scheduler.py
```

默认北京时间周一至周五 17:10 执行。

### 方法 B：系统 cron（更稳）

```cron
10 17 * * 1-5 cd /ABSOLUTE/PATH/a_share_watchlist_monitor && /ABSOLUTE/PATH/.venv/bin/python daily_job.py >> cron.log 2>&1
```

服务器时区不是 Asia/Shanghai 时，请按服务器时区换算或设置 `CRON_TZ=Asia/Shanghai`（取决于系统 cron 支持）。

## 5. 大宗交易口径

大宗交易直接读取东方财富数据中心公开的“每日明细”。页面会把命中的每一单分别
显示，金额统一换算为万元、成交量换算为万股、折溢率换算为百分比，并保留买卖双方
营业部和东方财富原文链接。

东方财富 Level-2 的逐笔还原属于权限型服务，本项目**不会绕过登录、订阅或反爬限制**。如果你有合法 Level-2 / Choice / Wind / iFinD / 聚宽等数据权限，可以新增 adapter 替换公开数据源。

## 6. 问董秘数据说明

问董秘栏目不受侧栏 6/12/24/48/72 小时时间窗口限制。程序根据代码自动判断市场：
深圳股票查询深交所互动易，上海主板及科创板查询上证 e 互动，北交所股票查询全景网
投资者关系互动平台。三个网站的栏目结构不同，因此仪表盘统一列出已获得公司回复的
“最新答复”，并保留对应平台原文链接。
历史数据库中的旧渠道互动记录不会被删除，但 V6 会在仪表盘概览、数据表和日报入口
统一过滤，避免旧记录再次显示或参与统计。外部平台暂无回复时，页面会明确显示暂无
资料，不会用其他市场的网站代替。
外部页面或接口临时失败时，错误会写入 `watchlist.log`，不会影响其他数据源。

## 8. GitHub 上传注意事项

上传时应把解压后目录里的 `app.py`、`collectors/` 等内容放在 GitHub 仓库根目录，
不要再次上传外层文件夹。`.gitignore` 已排除虚拟环境、缓存和运行日志；若仓库里已有
重复的 `Repository-name-a-stock-radar-main/` 目录，可以在确认根目录 V6 正常运行后
再删除该重复目录。定时任务只会提交 `data/watchlist.db` 和 `reports/`，不会继续提交
运行日志或缓存文件。
